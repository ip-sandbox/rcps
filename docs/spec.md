# コメント削除スクリプト 仕様書

Nov 20, 2026 · @あなた

## 1. 目的と適用範囲

自作ソースからコメントを削除する PowerShell スクリプトを作る。Windows 標準の PowerShell 5.1 で動き、コンパイルや外部ツールは不要とする（PowerShell 7 でも動くこと）。

- 対象：自分が作成したコード。OSS 由来のファイルは除外リストで対象外にする（8章）。
- 提供機能：単一ファイルを処理するコマンドと、ディレクトリ配下を一括処理する仕組みの2つ。
- やらないこと：構文チェック、コード整形、コメント以外の変更（空行の詰めは5章のルールに限る）。

## 2. 対象ファイル種別と判定方法

種別はファイル名だけで判定する（拡張子の大文字・小文字は区別しない）。中身を見ての判定（shebang など）はしない。表にないファイルは「対象外」として何もしない。

| 種別 | 判定条件 | 削除するコメント |
| --- | --- | --- |
| C/C++ | `.c` `.cpp` `.cc` `.h` `.hpp` `.hh` | `//` `/* */` |
| Java | `.java` | `//` `/* */` `/** */` |
| TypeScript | `.ts` | `//` `/* */` |
| CSS | `.css` | `/* */` |
| HTML | `.html` | `<!-- -->` |
| シェル | `.sh` | `#` |
| Makefile | ファイル名 `Makefile` `makefile` `GNUmakefile`、拡張子 `.mk` | `#` |
| 設定ファイル | `.conf` | `#`（行頭のみ） |

表は既定値。言語と拡張子・ファイル名の対応は、設定ファイルの `languages` で変更・追加できる（10章）。`.htm` は既定では対象外で、必要なら設定で html に追加する。

## 3. 構成

3つのファイルで構成する。一括処理は単一ファイルコマンドをファイルごとに呼び出すだけで、削除ロジックを持たない。

| ファイル | 役割 |
| --- | --- |
| `Remove-Comments.ps1` | ファイルパスを1つ受け取り、コメントを削除する（4章） |
| `Invoke-RemoveComments.ps1` | ディレクトリを走査し、対象ファイルごとに `Remove-Comments.ps1` を呼ぶ（8章） |
| `remove-comments.json` | 出力先、保持パターン、保持範囲、言語と拡張子の対応、除外リストなど、処理条件をすべて書く設定ファイル（両方から読む。10章） |

引数は最小限にし、それ以外の処理条件は設定ファイルにだけ書く。スクリプトは署名なしで配布するため、実行は `powershell -ExecutionPolicy Bypass -File ...` を想定する。

## 4. 単一ファイルコマンド（Remove-Comments.ps1）

1回の呼び出しでファイルを1つだけ処理する。引数は4つだけで、処理条件はすべて設定ファイル（10章）から読む。

```
Remove-Comments.ps1 -Path <file> [-Config <json>] [-OutPath <file>] [-DryRun]
```

| 引数 | 内容 |
| --- | --- |
| `-Path` | 処理するファイル（必須） |
| `-Config` | 設定ファイル。省略時の探し方は10章 |
| `-OutPath` | 結果の書き出し先。親ディレクトリがなければ作る。省略した場合は、設定の `output.mode` が `inPlace` のときだけ元ファイルを上書きし、それ以外は引数エラー（誤った上書きの防止）。`-DryRun` のときは何も書かないので省略してよい |
| `-DryRun` | ファイルを書かず、削除・保持の件数だけ出力する |

標準出力には結果を1行だけ出す（一括処理が集計に使う）。エラーの詳細は標準エラーに出す。

```
OK<TAB>src/main.cpp<TAB>removed=12<TAB>kept=3
ERROR<TAB>src/bad.cpp<TAB>code=3
UNSUPPORTED<TAB>README.md
```

- 成功時は `OK`、終了コード2は `UNSUPPORTED`、それ以外の失敗は `ERROR` と終了コードを出す。エラーの内容は標準エラーにだけ出す。
- `-DryRun` のときも成功なら `OK` の行を同じ形式で出す。
- `removed` と `kept` はコメント1つを1件として数える。連続する `//` 行は1行ずつ別に数える。保持範囲（7.2）の中のコメントとマーカーのコメントは `kept` に数える。
- `-OutPath` を省略して元ファイルを上書きするとき、設定の `output.backup` が `true` なら書き換える前に `<file>.bak` を作る（既にあれば上書きする）。

| 終了コード | 意味 |
| --- | --- |
| 0 | 成功（削除対象が0件でも成功） |
| 2 | 対象外のファイル種別 |
| 3 | 解析エラー（閉じていないコメントや文字列） |
| 4 | 保持範囲のエラー（START と END の対応が取れない） |
| 5 | 読み書き・文字コードのエラー |
| 6 | 正規表現の照合がタイムアウトした（7.1） |
| 9 | 引数・設定ファイルのエラー |
| 1 | 想定外の内部エラー（不具合） |

0以外のときは、出力先も元ファイルも一切書き換えない。

## 5. コメント削除の共通ルール

正規表現の置換ではなく、先頭から1文字ずつ読む状態機械でコメントを判定する。文字列や文字リテラルの中にある `//` や `/*` はコメントとみなさない。

削除後の行の扱い：

1. 行全体がコメント（前後が空白のみ）なら、行ごと削除する。
2. 行末コメントは、コメントとその直前の空白を削除する。`int a = 1; // x` → `int a = 1;`
3. 行の途中のブロックコメントは削除し、前後がくっつく場合は空白1つに置き換える。`a/**/b` → `a b`。ただし HTML では空白を入れない（`a<!-- x -->b` → `ab`。HTML ではコメントが字句の区切りにならず、空白を入れると表示が変わるため）
4. 複数行のブロックコメントは内側の行を削除する。開始前のコードは開始行に、終了後のコードは終了行に残す。
5. もともとある空行は残す。コメント削除で連続した空行は圧縮しない。
6. コメントを削除した行だけ行末の空白を削る。それ以外の行は1文字も変えない。

削除した行を空行として残し、行番号を維持するオプションは設けない。

## 6. 言語別ルール

言語ごとに、コメントとみなさない文脈（文字列など）を決める。ここにない構文は普通のコードとして扱う。

**C/C++**

- `"..."` と `'...'` はバックスラッシュのエスケープ込みで読み飛ばす。
- 生文字列 `R"delim( ... )delim"` は終端まで読み飛ばす。
- 行末 `\` で継続した `//` コメントは、次の行もコメントとして削除する（コンパイラと同じ解釈）。
- `#include <a/*b>` のような山括弧内は特別扱いしない（実際にはほぼ発生しない）。

**Java**

- `"..."` `'...'` に加え、テキストブロック `""" ... """` を読み飛ばす。
- Javadoc `/** */` も削除対象。残したい場合は保持パターンで指定する。

**TypeScript**

- `"..."` `'...'` とテンプレート文字列 `` `...${式}...` `` を読み飛ばす。`${}` の中はコードとして扱い、入れ子にも対応する。
- 正規表現リテラル `/.../` は直前のトークンから推定して読み飛ばす。完全な判定はできないため、誤判定の可能性が残る。
- `/// <reference ... />` は削除するとビルドに影響するため、固定で保持する（7章）。`///` と `<reference` の間の空白の有無や数は問わない（`///<reference` も保持）。

**CSS**

- `/* */` のみ。`//` はコメントではないので触らない（`url(//example.com)` を壊さない）。
- `"..."` `'...'` を読み飛ばす。

**HTML**

- `<!-- -->` のみ削除する。
- `<script>` と `<style>` の中は触らない（中の JS/CSS コメントも残る）。
- `<pre>` の中の `<!-- -->` も削除する（ブラウザもコメントとして扱うため）。`<textarea>` と `<title>` の中は文字列なので触らない。
- 空のコメント `<!-->` と `<!--->` は、ブラウザと同じくそこでコメントが終わるものとして削除する。
- 条件付きコメント `<!--[if ...]>` は固定で保持する。対になる閉じ側 `<!--<![endif]-->`（`<!--<![endif]` で始まるコメント）も固定で保持する。

**シェル（.sh）**

- `#` は単語の先頭にあるときだけコメント。`$#` `${#var}` `a#b` はコード。
- `'...'` `"..."` `` `...` `` `$(...)` の中は読み飛ばす（`$(...)` 内のコメントは削除対象）。
- ヒアドキュメント `<<EOF` `<<-EOF` `<<'EOF'` の本文は触らない。
- 1行目の shebang `#!` は固定で保持する。

**Makefile**

- タブで始まるレシピ行はシェルと同じルールで処理する。
- それ以外の行では、`\#` 以外の `#` 以降がコメント（make は引用符の中でも `#` をコメントと扱うため、引用符は考慮しない）。
- 行末 `\` で継続したコメントは次の行も削除する。
- `define ... endef` の中は触らない。

**設定ファイル（.conf）**

- 先頭の空白を除いて `#` で始まる行だけをコメントとして行ごと削除する。
- 行の途中の `#` は削除しない。`.conf` は形式がファイルごとに違い、`color = #fff` や URL の `#` のように値の一部である場合があるため。
- 引用符や行末 `\` の継続は考慮しない。

## 7. 例外（削除しないもの）

例外は3種類。どれか1つに当てはまれば、そのコメントは元のまま残す。

**7.1 保持パターン（コメント単位）**

- コメントの文字列（区切り記号を含む）に、指定した文字列のどれかが部分一致すれば、そのコメントを丸ごと残す。
- 複数指定でき、条件は OR。設定ファイルの `keep.patterns`（全言語共通）と `languages.<言語>.keepPatterns`（その言語だけ追加）で指定する。
- 正規表現ではなくリテラル文字列として比較する。大文字・小文字は区別する（`keep.caseSensitive: false` で区別しない）。
- 複数行のブロックコメントは、どこか1行でも一致すれば全体を残す。連続する `//` 行は1行ずつ別のコメントとして判定する。
- 自作コードの著作権表記は固定では残さない。残す場合は `Copyright` などを保持パターンに入れる。

正規表現での指定（`keep.regex`）：

- 部分一致の `keep.patterns` とは別のキーで指定する。両方を併用でき、どれか1つに一致すれば残す（OR）。
- .NET の正規表現（`System.Text.RegularExpressions`）を使う。grep や PCRE と細部が異なる。
- 照合はコメントの1行ごとに行う（区切り記号を含む、改行を除いた文字列）。`^` と `$` はその行の先頭と末尾。複数行のブロックコメントは、どこか1行でも一致すれば全体を残す。
- 大文字・小文字の区別は `keep.caseSensitive` に従う。
- JSON の中では `\` を二重に書く。例：`\d+` は `"\\d+"`。
- 正しくない正規表現は、起動時の設定チェックで設定エラー（終了コード9）にする。
- 1回の照合が1秒を超えたら打ち切り、そのファイルを終了コード6で止める（書き換えない）。無限に近いバックトラックを防ぐため。
- `.*` のような広いパターンは、すべてのコメントを警告なしに残す。設定を変えたときは `-DryRun` で保持件数を確認する。

**7.2 保持範囲（開始と終了のキーワードで囲む）**

```
// % DEL START
// something
int x = 0; // この行もそのまま
// % DEL END
```

- 開始キーワードを含むコメントの行から、終了キーワードを含むコメントの行までを、コードも空行も含めて一切変更しない（マーカー行自体も残す）。
- キーワードはコメントの中にあるものだけ有効。文字列中にあっても無視する。
- 既定値は `% DEL START` と `% DEL END`。設定ファイルの keepRegion で変更できる（指定できるのは1組のみ）。言語によらず同じキーワードを使う（HTML なら `<!-- % DEL START -->`、シェルなら `# % DEL START`）。
- 1ファイルに複数の範囲を置ける。入れ子は不可。
- 次の場合は終了コード4で停止し、ファイルを書き換えない：範囲内でもう一度開始が出た、開始なしで終了が出た、ファイル末尾まで終了がない。

保持範囲のキーワードは正規表現に対応しない（部分一致のみ）。パターンが意図しないコメントに一致すると、範囲の開始と終了がずれて大きな範囲を取り違えるため。

**7.3 固定で保持するもの（指定不要）**

| 対象 | 理由 |
| --- | --- |
| シェルの1行目 `#!` | 実行に必要 |
| TypeScript の `/// <reference ... />` | ビルドに必要 |
| HTML の条件付きコメント `<!--[if ...]>` と閉じ側 `<!--<![endif]-->` | 表示に影響する |

## 8. ディレクトリ一括処理（Invoke-RemoveComments.ps1）と OSS 除外

指定ディレクトリ配下を再帰的に走査し、対象ファイルごとに `Remove-Comments.ps1` を呼ぶ。削除ロジックは持たず、単一ファイルコマンドの終了コードと結果行を集計する。

```
Invoke-RemoveComments.ps1 [-Config <json>] [-Root <dir>] [-DryRun]
```

`-Root` は設定の `batch.root` より優先する。出力先、除外、ログはすべて設定ファイルから読む。

**処理の流れ**

1. 対象ディレクトリ（`-Root` または `batch.root`）配下のファイルを列挙する。`.git` `.svn` は常に走査しない。
2. 除外パターンに一致するファイルを `EXCLUDED`、`languages` のどの言語にも対応しないファイルを `UNSUPPORTED` とする。
3. 残ったファイルごとに、同じプロセス内で `Remove-Comments.ps1` の処理を呼び、終了コード・件数・エラー内容を受け取る（ファイルごとに powershell.exe を起動すると遅いため）。具体的には `Remove-Comments.ps1` をドットソースして、単一ファイル処理の関数を直接呼ぶ。削除ロジックは `Remove-Comments.ps1` にだけあり、一括処理は持たない（docs/design.md）。
4. エラーが出ても残りのファイルの処理を続ける。設定エラーのときだけは、1ファイルも処理せずに終了コード9で終わる。
5. 最後に件数を表示し、`log.path` が設定されていれば CSV を書く。

**出力先**

- `output.mode: "outDir"`：`output.outDir` に、対象ディレクトリと同じ構成で書き出す。`EXCLUDED` と `UNSUPPORTED` のファイルもそのままコピーし、出力先がそのままビルドできる状態にする。出力先が対象ディレクトリの内側にある場合はエラー。
- `output.mode: "inPlace"`：元ファイルを上書きする。`output.backup: true` で `<file>.bak` を残す。`EXCLUDED` と `UNSUPPORTED` には触らない。

**OSS 除外の指定**

- 除外はパスのパターンで指定する。対象ディレクトリからの相対パス、区切りは `/`、大文字・小文字は区別しない。
- `*` はディレクトリをまたがない任意の文字列、`**` は任意の階層。例：`third_party/**`、`**/vendor/**`、`src/lib/zlib*.c`。
- 指定元は2つで、両方を合算する：`exclude`（パターンの配列）と `excludeFiles`（1行1パターンで書いたテキストファイルの配列。`#` で始まる行と空行は無視）。OSS の一覧を別ファイルで管理する用途を想定する。

**ログ（CSV）**

| 列 | 内容 |
| --- | --- |
| path | 対象ディレクトリからの相対パス |
| status | `OK` / `EXCLUDED` / `UNSUPPORTED` / `ERROR` |
| exitCode | `Remove-Comments.ps1` の終了コード |
| removed / kept | 削除・保持したコメント数 |
| message | エラー内容、または一致した除外パターン |

一括処理自体の終了コードは、`ERROR` が0件なら0、1件以上なら1、設定エラーなら9。

**-DryRun**

- 各ファイルに `-DryRun` を付けて呼ぶ。出力先への書き出し、`EXCLUDED` と `UNSUPPORTED` のコピー、`.bak` の作成はしない。
- 件数の表示と CSV ログ（`log.path` があれば）は通常どおり書く。

## 9. 文字コード・改行・エラー処理

入力と同じ文字コード・改行で出力し、コメント以外のバイトは変えない。

**文字コード**

1. BOM があればそれに従う（UTF-8 / UTF-16LE / UTF-16BE）。
2. BOM がなければ UTF-8 として厳密に読み、失敗したら Shift\_JIS（CP932）とみなす。
3. 設定の `encoding` に `utf8` か `sjis` を指定した場合は判定しない（引数では指定しない）。
4. 書き出しは読んだ文字コードと BOM の有無をそのまま使う。PowerShell 5.1 の `Set-Content -Encoding UTF8` は BOM を付けてしまうため使わず、.NET で明示的にエンコードしたバイト列を書き出す。

**改行**

- CRLF / LF は行ごとに元のまま残す（混在ファイルもそのまま）。
- ファイル末尾の改行の有無も元に合わせる。

**エラー処理**

- 処理はすべてメモリ上で行い、最後に一時ファイルへ書いてから置き換える。途中で失敗しても元ファイルは壊れない。
- NUL 文字を含むファイルはバイナリとみなし、終了コード5で処理しない。
- 閉じていないコメント・文字列・ヒアドキュメントは終了コード3。エラーメッセージに開始行の番号を含める。

## 10. 設定ファイル（remove-comments.json）

処理条件はすべて1つの JSON ファイルに書き、単一ファイルコマンドと一括処理の両方が同じファイルを読む。言語と拡張子の対応もここで指定する。

**記述例**

```json
{
  "version": 1,
  "output": { "mode": "outDir", "outDir": "../out", "backup": false },
  "encoding": "auto",
  "keep": {
    "patterns": ["Copyright", "NOLINT", "@license"],
    "regex": ["^\\s*//\\s*@generated", "TICKET-\\d+"],
    "caseSensitive": true
  },
  "keepRegion": { "start": "% DEL START", "end": "% DEL END" },
  "languages": {
    "cpp":        { "extensions": [".c", ".cpp", ".cc", ".h", ".hpp", ".hh"] },
    "java":       { "extensions": [".java"], "keepPatterns": ["@formatter:"] },
    "typescript": { "extensions": [".ts"] },
    "css":        { "extensions": [".css"] },
    "html":       { "extensions": [".html", ".htm"] },
    "shell":      { "extensions": [".sh"] },
    "makefile":   { "extensions": [".mk"], "fileNames": ["Makefile", "makefile", "GNUmakefile"] },
    "conf":       { "extensions": [".conf"] }
  },
  "batch": { "root": "../src" },
  "exclude": ["third_party/**", "**/vendor/**"],
  "excludeFiles": ["oss-list.txt"],
  "log": { "path": "../out/remove-comments-log.csv" },
  "_comment": "_ で始まるキーはメモとして無視される"
}
```

**キー一覧**

| キー | 型 | 既定値 | 内容 |
| --- | --- | --- | --- |
| `version` | 数値 | `1` | 設定ファイルの形式の版。1以外はエラー |
| `output.mode` | `"outDir"` / `"inPlace"` | なし | 出力方法。一括処理では必須。4・8章 |
| `output.outDir` | パス | なし | 一括処理の出力先。`mode` が `outDir` のとき必須 |
| `output.backup` | 真偽値 | `false` | `inPlace` のとき `.bak` を残す |
| `encoding` | `"auto"` / `"utf8"` / `"sjis"` | `"auto"` | 入力の文字コード。9章 |
| `keep.patterns` | 文字列の配列 | `[]` | 全言語共通の保持パターン（部分一致）。7.1 |
| `keep.regex` | 文字列の配列 | `[]` | 全言語共通の保持パターン（.NET 正規表現）。7.1 |
| `keep.caseSensitive` | 真偽値 | `true` | `patterns` と `regex` で大文字・小文字を区別するか |
| `keepRegion.start` / `.end` | 文字列 | `"% DEL START"` / `"% DEL END"` | 保持範囲のキーワード（部分一致のみ）。7.2 |
| `languages.<言語>.extensions` | 文字列の配列 | 2章の表 | その言語として扱う拡張子（ドット付き） |
| `languages.<言語>.fileNames` | 文字列の配列 | makefile のみあり | 拡張子ではなくファイル名で対応付ける |
| `languages.<言語>.keepPatterns` | 文字列の配列 | `[]` | その言語だけに追加する保持パターン（部分一致） |
| `batch.root` | パス | なし | 一括処理の対象ディレクトリ。`-Root` が優先 |
| `exclude` | 文字列の配列 | `[]` | 除外パターン。8章 |
| `excludeFiles` | パスの配列 | `[]` | 除外パターンを書いたテキストファイル。8章 |
| `log.path` | パス | なし | 一括処理の CSV ログ。省略時は書かない |

**言語と拡張子の対応（languages）**

- 言語キーは `cpp` `java` `typescript` `css` `html` `shell` `makefile` `conf` の8種類で固定。削除ルール（6章）は実装に紐づくため、設定だけで新しい言語は追加できない。
- 書いた言語だけ既定値を置き換える。書かない言語は2章の既定値のまま。`"extensions": []` と書くとその言語を無効にできる。
- 拡張子とファイル名は大文字・小文字を区別しない。ファイル名の一致を拡張子より優先する。
- 同じ拡張子またはファイル名が2つの言語に割り当てられていたら、設定エラー（終了コード9）。

**読み込みのルール**

1. 探す順番：`-Config` で指定したファイル → カレントディレクトリの `remove-comments.json` → スクリプトと同じフォルダの `remove-comments.json`。どれもなければ組み込みの既定値だけで動く（ただし `output.mode` がないので、`-OutPath` なしの単一処理と一括処理はエラー）。
2. 優先順位：引数 > 設定ファイル > 組み込みの既定値。引数で上書きできるのは `-OutPath` と `-Root` だけ。
3. 設定内の相対パスは、設定ファイルがあるフォルダを基準に解決する。
4. 未知のキーや型の違いは設定エラー（終了コード9）。綴り間違いを見逃さないため。`_` で始まるキーはメモとして無視する。
5. JSON 内に `//` コメントは書けない（PowerShell 5.1 の `ConvertFrom-Json` が対応していないため）。メモは `_comment` などのキーで書く。
6. 設定ファイル自体は UTF-8（BOM の有無は問わない）。
7. 一括処理は起動時に1回だけ設定を検証し、エラーがあれば1ファイルも処理せずに終了する。

## 11. 決定事項

未決だった点は、すべて次のとおり決まった（本文に反映済み）。

- `.he` は `.hh` の誤記。C/C++ の既定の拡張子は `.c` `.cpp` `.cc` `.h` `.hpp` `.hh`。
- `.mk` は既定で対象に含め、`.htm` は含めない（設定で追加可）。
- HTML の `<script>` `<style>` の中は触らない。
- 削除した行を空行で残すオプションは設けない。
- 著作権表記は固定では残さず、保持パターンで運用する。
- 保持範囲のキーワードは1組のみ。
- `outDir` 出力では、除外・対象外のファイルもコピーする。
- 文字コードが UTF-8 で読めなければ Shift\_JIS とみなす。
- 引数は最小限にし、処理条件は設定ファイルにまとめる。言語と拡張子の対応も設定で指定できる（10章）。

* `.conf`（設定ファイル）を対象に追加する。コメントは `#`。

- 保持パターンは正規表現にも対応する。部分一致の `keep.patterns` とは別に `keep.regex` で指定する。
- 保持範囲（`keepRegion`）のキーワードは部分一致のままとし、正規表現には対応しない。
- 設定ファイルの形式は JSON のままとする（`.psd1` などにはしない）。
- 入力の文字コードは引数ではなく設定の `encoding` で指定する（`-Encoding` 引数は設けない）。
- `.bak` は単一ファイルコマンドが `output.backup` を見て作る。
- 結果行に `ERROR` と `UNSUPPORTED` の形式を加える。件数はコメント単位で数える（4章）。
- 一括処理の `-DryRun` でも CSV ログは書く（8章）。
- 実行時に追加のモジュールやツールは不要（PowerShell と .NET の標準機能だけを使う）。テストも Pester を使わず、自作の `tests/Run-Tests.ps1` で実行する。
